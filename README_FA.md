# PatchGuard — اعتبارسنجی خودکار وصله‌های امنیتی

**دانشگاه صنعتی شریف · درس امنیت داده و شبکه · پروژه اول · گروه ۱۱**

اعضای گروه: پوریا امیرنیا، دانیال آذرنیا، محمدجواد خوشدونی فراهانی و محمدمتین انصاری.

PatchGuard نسخه آسیب‌پذیر و نسخه وصله‌شده یک برنامه C/C++ را به‌صورت واقعی کامپایل و اجرا می‌کند، خطاهای ASan/UBSan را استخراج می‌کند، رفتار برنامه را با قرارداد مستقل مقایسه می‌کند، یافته‌ها را به تغییرات سورس پیوند می‌دهد و بسته‌های بازتولید و گزارش CI/CD تولید می‌کند.

## اجرای مستقل

پیش‌نیاز: Linux x86-64 یا WSL2، Docker فعال، Python 3 و Git. اجرای کدهای آسیب‌پذیر فقط در محیط ایزوله مجاز است.

```bash
git clone https://github.com/pooryaamirniya/DNS_Project_G11.git
cd DNS_Project_G11
bash tools/docker_run.sh
python3 -m unittest discover -s tests -v
python3 tools/blind_patch_test.py
python3 tools/quality_gate.py --strict
```

ترتیب دستورها مهم است: اولین اجرا ورودی‌های رگرسیون کمینه‌شده را می‌سازد و آزمون‌های واحد آن‌ها را بررسی می‌کنند. نتیجه مطلوب به ترتیب `Scenario matrix PASS`، موفقیت ۱۷ آزمون، `9/9 passed` و `Quality Gate: PASS` است.

## اهداف و نسخه‌ها

| هدف | نقص اصلی | نسخه‌ها |
|---|---|---|
| `frame` | Stack Buffer Overflow در یک مفسر آموزشی پیام | `base`، `correct`، `incomplete`، `regression` |
| `cjsonreal` | CVE-2024-31755 در تابع `cJSON_SetValuestring` کتابخانه واقعی cJSON | نسخه آسیب‌پذیر upstream `v1.7.17`، نسخه اصلاح‌شده `v1.7.18`، دو وصله آزمایشی ناقص و رگرسیونی |

نسخه‌های ناقص و رگرسیونی cJSON وصله رسمی منتشرشده نیستند؛ برای آزمون طبقه‌بندی ابزار ساخته شده‌اند. منشأ فایل‌های اصلی در `targets/cjsonreal/source_manifest.json` و رفتار مرجع در `docs/oracle-cjsonreal.md` ثبت شده است.

## کدهای خروج و شواهد

| کد | معنی |
|---|---|
| `0` | وصله در محدوده آزمون موفق است. |
| `10` | آسیب‌پذیری باقی است یا خطای امنیتی دیگری تأیید شده است. |
| `20` | رگرسیون عملکردی مشاهده شده است. |
| `30` | خطای Build یا پیکربندی رخ داده است. |
| `40` | شواهد برای داوری قطعی کافی نیست. |

| فایل / پوشه | شرح |

## ارزیابی یک وصله جدید

فایل C باید در پوشه پروژه قرار بگیرد و با رابط هدف موردنظر سازگار باشد:

```bash
python3 tools/evaluate_candidate.py --target cjsonreal --source candidate_sources/changed.c
```

کد فایل و ورودی‌های واقعی مبنای تصمیم هستند، نه نام فایل یا برچسب وصله. در صورت تغییر بنیادی رابط ورودی یا سیستم ساخت، تنظیمات هدف باید متناسب با آن اصلاح شوند.

## دامنه و محدودیت‌ها

آزمایش‌های موفق اثبات نبود همه آسیب‌پذیری‌های ممکن نیستند. هم‌پوشانی با Diff نشان‌دهنده ارتباط شواهد است، نه لزوماً رابطه قطعی علی. آزمون‌های وصله با نام ناشناخته از هدف‌های همین پروژه تولید می‌شوند؛ بنابراین تعمیم به هر تغییر مستقل خارجی را اثبات نمی‌کنند.
