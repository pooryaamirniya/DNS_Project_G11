# مرحله چهارم — بازبینی مستقل شواهد و کیفیت PatchGuard

این بسته «نمره کامل» را تضمین نمی‌کند. هدفش این است که وابستگی به خروجی ظاهری `Scenario matrix PASS` و `Blind patch matrix 9/9 passed` را کم کند و بازرسی مستقل شواهد ایجاد کند.

## آزمایش‌های بازبینی

1. بررسی هویت و SHA-256 فایل‌های upstream cJSON از هر دو release، و وجود معیار صحت مستقل.
2. بررسی دقیق شش سناریوی اصلی: کد خروج، چهار باینری release/sanitized، hash نسخه‌های سورس و ۳ تکرار آزمون امنیتی، شواهد hardening، correlation و بسته‌های بازتولید.
3. اطمینان از اینکه وصله صحیح واقعاً یک خطای بازتولیدشده را رفع و رفتار عادی را حفظ کرده، وصله ناقص واقعاً آسیب‌پذیری تأییدشده را باقی گذاشته و وصله رگرسیون تست معتبر را خراب کرده است.
4. بررسی ۹ آزمون blind با خواندن manifest، summary و هر ۹ فایل گزارش اصلی موتور، و کنترل **وضعیت تفصیلی** `security_status` و `functionality_status` جدا از کد خروج.
5. اطمینان از وجود پایپ‌لاین رسمی و پایپ‌لاین کیفیت جدید.

## اجرا در WSL2

از ریشه مخزن:

```bash
python3 -m unittest discover -s tests -v
python3 tools/quality_gate.py --strict
cat artifacts/quality-gate/quality_report.md
```

این اسکریپت فقط فایل‌ها را می‌خواند و گزارش تولید می‌کند؛ هیچ باینری آسیب‌پذیری را اجرا نمی‌کند. باید **بعد از اجرای ماتریس ۶تایی و ۹تایی** اجرا شود.

با توجه به سابقه خطای `cwd` در WSL روی `/mnt/c`، اگر پایتون خطای `FileNotFoundError` موقع import داد، از `/tmp` اجرا کنید:

```bash
PROJECT="$PWD"
(cd /tmp && python3 "$PROJECT/tools/quality_gate.py" --strict)
```

## معنی خروجی

- `Quality Gate: PASS`: همه بررسی‌های قابل ارزیابی در محدوده شواهد موجود موفق شده‌اند.
- `Quality Gate: FAIL`: فایل یا شاهد ضروری ناقص/ناسازگار است؛ **خروجی خطا را به همراه گزارش** بررسی کنید، هرگز به زور PASS ندهید.
- حالت `--strict` هشدارهایی مثل نبود هم‌بستگی قابل استناد بین خطای runtime و تغییرات Diff را نیز blocker می‌کند.

## نارسایی‌های باقیمانده تا نمره کامل

- امضای مدرس یا دستیار برای انتخاب target و معیار صحت، همچنان باید مستند شود.
- `frame` یک برنامه کوچک آموزشی است و `cjsonreal` یک کتابخانه واقعی؛ این ترکیب با حداقل الزام «حداقل یک هدف واقعی» سازگار است، در صورت تأیید مدرس.
- آزمون‌های blind تولیدی، جایگزین کامل وصله‌های کاملاً ناشناخته استاد نیستند؛ ممکن است اصلاح adapter/build برای یک سورس خارجی نیاز باشد.
- هر یک از چهار عضو باید سهم واقعی، کد و منطق مربوطه، شواهد آزمایش و تغییرات زنده را بلد باشند؛ دفاع مستقل و مشارکت واقعی شرط نمره شخصی است.
- نتیجه ابزار از روی ۶+۹ تست، اثبات نبود تمام آسیب‌پذیری‌ها نیست.
